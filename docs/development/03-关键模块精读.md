## 3. 四个关键算法

### 3.1 终端能力探测与颜色降级

探测顺序（`is_terminal` + `_detect_color_system`）：显式指定 → 是否重定向 → 是否 Jupyter
→ `TERM=dumb` → `COLORTERM` 是否含 truecolor/24bit → `TERM` 是否含 256color/direct。
颜色能力等级从高到低：TRUECOLOR → EIGHT_BIT → STANDARD → WINDOWS → 无。
降级发生在渲染期（`Style.render` → `Color.downgrade`），组件层完全不需要知道终端能力。

### 3.2 按单元格宽度的换行与裁剪

`cells.chop_cells` 逐字符累加宽度，宽字符（2 格）若只剩 1 格则换行而不是切开；
`Segment.adjust_line_length` 用背景样式补齐到恰好 `width` 格。
换行本身也是 `Segment`（`Segment.line()`，text 为空、control 为换行控制码）。

### 3.3 自适应列宽分配（table.py）

对每列每个单元格求 `Measurement(minimum, maximum)`；若总最大宽度放得下就各取最大，
否则把超出量按“可压缩量 = maximum − minimum”等比分配；最后逐列渲染再拼接。
复杂度 O(行×列)，无迭代收敛。

### 3.4 输出缓冲与录制

`_buffer`（录制的 Segment 列表）+ `_buffer_index`（capture 起点）→
`export_text` 只取纯文本、`export_html` 把 `Style.get_html_style` 转行内 CSS、
`export_svg` 自己实现“ANSI 序列 → SVG `<text>`/`<tspan>`”的转换（不经过 HTML 路径）。

## 4. 数据设计：核心结构与其不变量

| 结构 | 形态 | 不变量 |
| --- | --- | --- |
| `Segment` | `NamedTuple(text, style, control)` | 不可变；`cell_length` 只统计 `text`；控制段 `text == ""` |
| `Style` | `__slots__` 类，缓存 `_hash` | 不可变、可哈希；`Style.null()` 与“无样式”语义不同；`meta`/`link` 参与相等性 |
| `Color` | `NamedTuple(name, type, number, triplet)` | 四种 `ColorType` 互斥；`is_default` 表示用终端默认色 |
| `Theme` | 栈式 `_theme_stack` | 栈顶优先；支持 `inherit` |
| `ConsoleOptions` | 不可变快照 | `update*` 返回新对象；`min_width <= max_width` |
| `ControlCode` | `NamedTuple(control_type, param)` | 控制码不参与宽度计算 |

## 5. 开发经验提炼

1. **用不可变上下文传递环境**：`Panel` 需要“宽度减 4”时只需 `options.update_width(w-4)`，
   不必担心影响兄弟节点，也不存在异常路径污染问题。
2. **把“度量”与“绘制”分成两个协议**：打破“先量后排、排完才能量”的循环依赖。
3. **用中间表示消灭组合爆炸**：N 个组件 × M 种输出从 N×M 降到 N+M。
4. **平台差异用后端隔离**：Win32 细节全部关在 `_win32_console.py`，且优先尝试 VT 序列，
   只在真正需要时才走传统 API——比“按系统版本硬编码分支”稳健。
5. **性能上相信缓存局部性**：`cells` 用 `lru_cache` 缓存单字符与整串宽度，`Style` 缓存
   `__hash__`，`Segment.cell_length` 是缓存属性；三者共同保证渲染表格时宽度计算不是瓶颈。

## 6. 从精读到维护需求的推导

精读过程中发现的三处能力缺口，直接成为本次维护需求的来源：

| 发现 | 影响 | 对策 |
| --- | --- | --- |
| `Text.wrap` 是贪心首次适配（`_wrap.py`），无全局代价 | 右边缘参差不齐，长单词导致大片空白 | 实现 Knuth-Plass 总代价最优断行 |
| 完全没有连字算法 | 长单词无法在词内断开 | 实现 Liang 模式连字 + 精确词表 |
| 宽字符只算宽度，不做断行位置约束 | 中文标点会出现在行首/行尾 | 实现中日韩禁则处理 |
| 但 `cells.cell_len` 已提供可靠度量 | 新引擎可以与之对齐 | 复用 `cell_len`，不自建度量 |

这四条构成了第四部分"维护功能"的直接依据：**缺口来自精读，方案受精读约束**。
