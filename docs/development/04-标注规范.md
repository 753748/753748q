# 代码标注规范与标注标记体系

> 本文档定义本次实践对 Rich 关键模块（终端渲染管线，约 8364 行）进行中文标注时采用的
> 统一规范。规范先定、后标注，保证 7 个文件、300 余个类与方法上的标注风格一致、可检索。

## 1. 标注原则

1. **只增不改**：只添加注释与文档字符串，绝不修改任何可执行语句、导入、装饰器、
   函数签名、默认值或类型注解。这一点通过 AST 比对做机械验证（见第 4 节）。
2. **解释“为什么”优先于“是什么”**：`self.width = width` 这样的行不需要注释；
   “这里必须先反转再缓存，否则主题栈回退时会命中过期样式”这样的行才需要。
3. **标注自己读懂的代码**：不确定的行为必须先查调用方（`grep`）再写，不臆测。
4. **就事论事**：不评论代码风格、不做重构建议，避免把标注写成 review 意见。
5. **粒度随重要性变化**：核心算法密集标注，简单属性访问器只给一行【功能】。

## 2. 标记体系

### 2.1 文件级标记

每个文件在模块文档字符串之后插入一个分隔块：

```
# ---------------------------------------------------------------------------
# 【模块定位】本文件在整体架构中的位置：它解决什么问题、依赖谁、被谁依赖
# 【关键数据结构】本文件的核心结构与必须成立的不变量
# 【设计要点】2-5 条：为什么这样设计，以及代价是什么
# 【阅读建议】建议的阅读顺序（长文件给出具体行号区间）
# ---------------------------------------------------------------------------
```

### 2.2 类级标记

在 `class` 行之前插入：

```
# 【职责】这个类负责什么
# 【关键属性】重要属性及其含义、单位
# 【不变量】构造后必须始终成立的条件
# 【协作】它与哪些类/模块配合，通过什么接口
```

### 2.3 方法级标记

在 `def` 行之前插入，只写有信息量的标签：

| 标签 | 用途 |
| --- | --- |
| 【功能】 | 一句话说明做什么 |
| 【算法】 | 非平凡算法的步骤（贪心/动态规划/查找/降级等） |
| 【参数】 | 不易理解的参数、单位、取值范围 |
| 【返回】 | 返回值及特殊情况（`None`、空集合、异常） |
| 【注意】 | 陷阱、边界条件、性能、平台差异 |

### 2.4 语句级标记

直接写在被解释语句的上一行：

| 标记 | 用途 | 示例场景 |
| --- | --- | --- |
| 【要点】 | 实现上的关键一步 | “先按宽度切分再叠加样式” |
| 【为什么】 | 设计动机，防止后人误改 | “这里必须用 `<` 而非 `<=`” |
| 【易错】 | 容易误解或改错的边界 | “空字符串也必须占用 0 格而非跳过” |
| 【优化】 | 性能相关 | “缓存整数哈希，避免每次重算” |
| 【兼容】 | 平台/版本差异 | “Windows 传统控制台不支持 ANSI” |
| 【约束】 | 必须与其它文件保持一致的约定 | “必须与 cells.cell_len 保持一致” |

## 3. 检索方式

标注标记统一使用全角方括号，因此可以直接按标记检索，例如：

```powershell
# 找出所有平台兼容相关的标注
Select-String -Path src/annotated/rich/*.py -Pattern '【兼容】'

# 找出所有必须跨文件保持一致的约定
Select-String -Path src/annotated/rich/*.py -Pattern '【约束】'

# 统计标注密度
(Select-String -Path src/annotated/rich/console.py -Pattern '【' -AllMatches).Matches.Count
```

## 4. 标注正确性的机械验证

标注不改变行为这一点，用 AST 比对证明。方法：把标注后文件与上游原始文件的
AST 分别“去掉所有文档字符串”（模块/类/函数的首条字符串表达式），再比较
`ast.dump` 的结果；两者必须完全相等。

```python
import ast, pathlib

def norm(path):
    tree = ast.parse(pathlib.Path(path).read_text(encoding="utf-8"))
    for node in ast.walk(tree):
        if isinstance(node, (ast.FunctionDef, ast.AsyncFunctionDef, ast.ClassDef, ast.Module)):
            if (node.body and isinstance(node.body[0], ast.Expr)
                    and isinstance(node.body[0].value, ast.Constant)
                    and isinstance(node.body[0].value.value, str)):
                node.body.pop(0)
    return ast.dump(tree)

base = pathlib.Path("src/original-provided/rich")
ann = pathlib.Path("src/annotated/rich")
for name in ["console.py", "segment.py", "style.py", "color.py", "theme.py", "text.py"]:
    print(name, "OK" if norm(base / name) == norm(ann / name) else "MISMATCH")
```

此外还执行了行为级验证：把 `src/annotated` 作为包路径运行 Rich 自带的完整测试套件，
结果与基线一致（12 项环境相关失败、1063 项通过），说明标注既未改变语法结构，
也未改变运行行为。
