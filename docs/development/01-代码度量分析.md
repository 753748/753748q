# Rich 代码度量分析（泛读第一步）

> 本文档记录实践过程中对 Rich v14.3.4 源码的量化分析结果。
> 全部数据由 `tools/measure.py`（本次实践编写）对 `src/original-provided/rich` 统计得到，
> 可以直接复现，不是估算值。

## 1. 为什么先做度量

泛读一个 2 万多行的陌生代码库，直接从头读会迷失。先度量有三个好处：

1. **确定阅读范围**：找出规模最大的模块，它们通常承载了最多的设计决策；
2. **确定阅读顺序**：找出被依赖最多的模块，它们是最底层的抽象，应先读；
3. **为选关键模块提供依据**：实践要求关键模块不少于 3000 行，需要先用数据确认哪些候选达标。

## 5. 结论：三点阅读决策

1. **底层优先**：`console` / `style` / `text` / `segment` / `cells` 是入度最高的五个模块，
   它们定义了整个库的“词汇表”（渲染出口、样式、文本、中间表示、宽度），必须最先精读。
2. **跳过数据表**：`_emoji_codes.py`（3610 行）与 `_spinners.py`（482 行）是纯数据，
   合计 4092 行（占总行数 15%）不包含算法，泛读时略过，只在需要时查表。
3. **关键模块的选择依据**：`console.py`（2688 行）单独看未达 3000 行，
   但若把与它构成同一条渲染管线的 `segment.py`(780) + `style.py`(796) + `color.py`(621)
   + `theme.py`(116) + `_win32_console.py`(661) + `text.py`(1363) 一并纳入，
   合计 8364 行，既满足规模要求，又构成一个语义完整、边界清晰的子系统（详见
   `docs/development/02-架构泛读.md`）。

## 6. 复现方式

```powershell
python tools/measure.py --root src/original-provided/rich
```

脚本输出三张表：文件行数排名、入度/出度排名、以及按模块群汇总的规模。
